최종 수정: 2026-11-05

## 1. 엔진

| 항목 | 결정 | 비고 |
|---|---|---|

## 1.1 HD-2D 구현 방식

HD-2D는 언리얼 엔진으로 처음 만들어진 스타일입니다 (Octopath Traveler, UE4). 구현 요소는 다음과 같습니다.

| 요소 | 구현 |
|---|---|
| 스프라이트 | Paper2D 플러그인 또는 스프라이트 텍스처를 붙인 평면 메시. 카메라를 향하도록 배치 |
| 배경 | 큐브와 단순 메시에 픽셀 텍스처를 입힌 3D 공간 |
| 텍스처 | Nearest 필터, 밉맵 없음으로 픽셀 선명도 유지 |
| 카메라 | 좁은 FOV의 원근 카메라로 디오라마 느낌. 픽셀 떨림 방지를 위해 위치 스냅 검토 |
| 조명 | 동적 포인트 라이트와 스포트 라이트가 스프라이트에도 영향을 주도록 Lit 마스크 머티리얼 사용 |
| 후처리 | 틸트 시프트 피사계 심도, 블룸, 비네팅, 컬러 그레이딩 |
| 그림자 | 스프라이트가 그림자를 드리우도록 설정. Lumen 사용 여부는 Mac 성능 확인 후 결정 |

2D 게임플레이 물리가 필요하면 3D 물리를 한 평면에 고정하여 사용합니다.

## 2. 플랫폼

### 2.1 Windows
- 최소 OS: Windows 10 64비트
- 렌더링: DirectX 12 (SM6) 기본, DirectX 11 폴백 여부는 성능 목표 확정 후 결정
- 빌드 도구: Visual Studio 2022 (UE 권장 워크로드 설치)

### 2.2 macOS
- 최소 OS: UE 해당 버전이 지원하는 최소 macOS 버전 (프로젝트 생성 시 확인하여 기록)
- 아키텍처: Apple Silicon 네이티브 필수, Intel 지원 여부는 미정
- 렌더링: Metal
- 빌드 도구: Xcode (UE 해당 버전이 요구하는 Xcode 버전)
- 주의: macOS 패키징은 macOS 머신에서만 가능합니다. Windows에서 Mac 빌드를 만들 수 없습니다.

### 2.3 양 플랫폼 공통 원칙
- 플랫폼별 코드는 `PLATFORM_WINDOWS`, `PLATFORM_MAC` 매크로로 격리하고 최소화
- 매 마일스톤마다 양 플랫폼 패키징 빌드를 만들어 동작 확인
- 셰이더 컴파일 시간 차이를 고려하여 DDC(Derived Data Cache) 공유 검토

## 4. 버전 관리

### 4.1 Git 전략
- 기본 브랜치: `main`
- 작업 브랜치: 기능 단위로 생성, PR로 병합
- 바이너리 에셋(`.uasset`, `.umap`, 텍스처, 오디오 등)은 Git LFS로 관리
- 동시 수정 충돌이 잦은 `.umap`, 대형 Blueprint는 작업 전 팀에 알리는 규칙 적용 (파일 잠금은 LFS lock 사용 검토)

### 4.2 저장소에 포함하지 않는 것
- `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`
- `.vs/`, `.idea/`, `*.sln`, `*.xcworkspace` 등 IDE 생성물
- 언리얼 프로젝트 골격을 만들 때 `.gitignore`와 `.gitattributes`를 함께 추가합니다.

## 5. 프로젝트 구조 (예정)

```
ProjectB/
  docs/                  기획과 기술 문서
  ProjectB.uproject
  Config/                엔진, 게임, 입력 설정
  Content/               에셋 (LFS)
    ProjectB/            게임 고유 콘텐츠
    ThirdParty/          외부 에셋
  Source/
    ProjectB/            게임 모듈 (C++)
  Plugins/               프로젝트 전용 플러그인
```

콘셉트가 확정되면 `Content/ProjectB/` 하위 폴더 규칙을 정합니다.

## 6. Steam 연동

| 항목 | 방식 |
|---|---|
| SDK | Steamworks SDK (언리얼 `OnlineSubsystemSteam` 플러그인) |
| 필수 기능 | Steam 오버레이, 도전과제, 클라우드 세이브 |
| 선택 기능 | 리더보드, Rich Presence, 워크숍 (게임 콘셉트에 따라 결정) |
| 멀티플레이 | 미정. 필요하면 Steam Networking Sockets 기반 설계 |
| 테스트 | Steamworks에서 발급한 App ID와 `steam_appid.txt`로 개발 중 테스트, 출시 전 제거 |

Steamworks SDK 버전은 언리얼 엔진 버전이 기본으로 포함하는 것을 사용하고, 더 높은 버전이 필요하면 의사결정 기록에 남깁니다.

## 7. 빌드와 자동화

- 1단계: 로컬에서 수동 패키징 (Windows와 macOS 각각)
- 2단계: 빌드 스크립트 작성 (UAT `BuildCookRun` 래핑), 양 플랫폼 공통 인자 통일
- 3단계: CI 검토. 언리얼은 빌드 환경이 무겁기 때문에 자체 빌드 머신 또는 유료 러너가 필요하며 수직 슬라이스 이후 도입 여부 결정
