# 14. 포커 디펜스 (가칭)

다른 세션에서 넘어온 기획 메모(아이디어 단계)를 정리하고, 첫 프로토타입을 만들었다.
프로토타입: [prototype/poker-defense](../prototype/poker-defense/README.md)

## 1. 한 줄 요약
포커 카드로 타워를 세우는 디펜스 게임. 카드 한 장이 타워 하나이고, 인접한 타워끼리 포커 족보가 맞으면 시너지가 발동한다. 그래픽은 도형만 사용한다.

## 2. 배경 / 목표 (메모의 결정 사항)
- 소규모 유료 게임 (판매가 1~2천원 수준). 가볍게, 빨리 만들어서 내본다
- 도형(원, 삼각형, 사각형 등)만으로 모든 그래픽을 구성
- 이전 시도에서 얻은 교훈
  - 스택 포커(내려오는 카드를 클릭해 족보 만들기): 화면에서 족보를 눈으로 찾는 것이 고민이 아니라 노동에 가까워 보류
  - 테트리스 + 디펜스: 비슷한 게임이 이미 많아 보류
- 디펜스는 웨이브 사이에 숨 돌리는 템포가 있어서, 그때 패를 보고 고민하는 구조가 잘 맞음

## 3. 핵심 루프
1. 웨이브 사이에 카드 몇 장을 뽑는다
2. 카드를 맵에 놓아 타워로 설치하거나, 손에 들고 다음 웨이브까지 아껴 둔다
3. 웨이브를 막는다
4. 반복. 중간중간 규칙을 바꾸는 보상을 고른다 (v1에는 없음)

## 4. 핵심 메커닉 (메모의 제안 방향)
- 카드 = 타워. 무늬 = 속성/공격 타입, 숫자 = 공격력
- 인접 타워의 카드 조합이 족보가 되면 시너지. 족보마다 효과를 다르게 해서 크기만이 아니라 상황에 따라 고르게
  - 예: 원 페어 공격력, 플러시 범위, 스트레이트 연사, 풀하우스 범위+연사, 포카드 강력한 한 방
- 핵심 고민: "하트 7 옆에 하트 9를 둬서 플러시를 노릴까, 스페이드 7을 둬서 페어를 노릴까"
- 고르는 재미 장치: 카드를 쓰면 없어진다, 손패 칸 제한, 족보마다 효과가 다르다

## 5. 미정 사항 → v1 프로토타입에서 고른 기본값
| 미정 사항 | v1 기본값 | 이유 |
|---|---|---|
| 시너지 단위 | 카드 한 장 = 타워 + 인접 시너지 | 메모 추천안 |
| 인접 판정 | (v1.2) 상하좌우로 붙은 2~5장, 모양 상관없음. 타워 하나는 족보 하나에만 | v1은 가로·세로 한 줄이었으나 ㄴ자로 놓아도 안 되는 게 어색하다는 피드백 |
| 덩어리 안 족보 고르기 | 큰 족보부터 겹치지 않게 | 7 7 7이면 페어가 아니라 트리플, 7 7 5 5 5면 풀하우스 |
| 플러시·스트레이트 장수 | 플러시 3~5장, 스트레이트 2~5장. 장수가 많을수록 강함 | 5장만 인정하면 초반에 거의 안 나옴. 이어진 숫자 2장도 효과가 있어야 페어와 맞음 (사용자 피드백) |
| 덱 구조 | 고정 52장 (A~K × 4무늬) | 루프 손맛 확인이 먼저. 덱빌딩은 다음 |
| 맵 | 판마다 무작위 지그재그 길 (길이 34~46칸) + 길 아닌 칸 자유 배치, 16 × 10칸 | 사용자 요청. 판마다 배치 고민이 달라짐. 길이 범위로 난이도 흔들림을 줄임 |
| 카드 공급 | 처음 5장, 웨이브마다 3장, 손패 최대 7장 | 아껴 두기와 버리기 고민 |
| 교체 | 타워 위에 카드를 놓으면 교체 (원래 카드는 버려짐) | 족보 다시 짜기 |
| 무늬 → 도형 | ♠ 파란 삼각형(저격), ♥ 빨간 원(폭발), ♦ 노란 마름모(연사), ♣ 초록 사각형(둔화) | 메모 예시 그대로 |
| 숫자 표현 | 도형 안에 글자 (2~10, J Q K A) | 점 개수는 10 이상에서 읽기 어려움 |
| 보상 | 없음 | 루프 먼저 |
| 엔진 | 웹 프로토타입 (확정 아님) | |

## 6. v1 시험 결과
| 봇 (6판) | 결과 |
|---|---|
| 족보를 생각하는 봇 | 5판 전부 통과(15웨이브), 1판 15웨이브에서 실패, 남은 목숨 평균 8.7 |
| 족보를 생각 안 하는 봇 | 6판 모두 11웨이브에서 실패 |

적 체력은 웨이브마다 ×1.37. 족보를 쓰지 않으면 후반을 못 버티게 맞췄다.

## 7. 확인할 것 (플레이 테스트)
- 놓기 전 고민이 생기는가 (페어로 바로 쓸까, 플러시를 기다릴까)
- 손패를 아끼는 선택이 실제로 이득이 되는 순간이 있는가 (봇은 안 아끼고도 이김 → 아끼기 보상이 약할 수 있음)
- 무늬별 공격 차이가 체감되는가
- 다음 단계 후보: 웨이브 사이 보상(규칙 카드, docs/11), 덱빌딩, 맵 여러 개

## 8. 범위 가이드 (메모)
1~2천원 규모. 핵심 루프 프로토타입 → 족보 시너지 손맛 확인 → 도형 아트/이펙트 → 볼륨(스테이지, 보상).

## 9. v1.1 수정 (플레이 피드백)
| 피드백 | 수정 |
|---|---|
| 4♥ 옆 3♥처럼 이어진 숫자 2장은 아무 효과가 없다 | 스트레이트를 2장부터 인정 (연사 ×1.25). 페어와 같은 최소 장수 |
| 길도 매판 랜덤으로 | 무작위 지그재그 길. 가로 2~4칸, 위아래 2칸 이상 꺾기, 세로 구간끼리 붙지 않음, 길이 34~46칸만 |
| (같이 손봄) 시너지 선이 도형 숫자를 가림 | 족보에 든 칸들을 둥근 테두리로 감싸고 이름표는 테두리 위쪽에 |

봇 10판 (무작위 길, 적 체력 웨이브마다 ×1.35): 족보를 생각하는 봇 6판 통과·4판 15웨이브 실패, 생각 안 하는 봇은 11~12웨이브 실패.

## 10. v1.2: 모양 상관없는 족보 + 연쇄
피드백: ㄴ자로 배치하면 족보가 안 되나? → B안(모양 상관없이)으로, 가로세로 퍼즐처럼 연결되면 연쇄 효과도.

| 결정 | 이유 |
|---|---|
| 상하좌우로 붙은 2~5장이면 모양 상관없이 족보 | 붙여 놓으면 족보가 되는 게 자연스러운 손놀림 |
| 덩어리 안 모든 연결 묶음(최대 5장)을 따져 큰 족보부터, 겹치지 않게 | 타워 하나 = 족보 하나. 덩어리를 어떻게 나눌지가 고민거리 |
| 연쇄: 맞닿은 족보들은 하나의 연쇄, 족보 하나마다 공격력 +25% | 가로세로 퍼즐처럼 족보를 이어 붙이는 재미. 큰 덩어리를 만들수록 이득 |
| 가로·세로 겹침 보너스 삭제 | 타워 하나가 족보 하나에만 들어가므로. 연쇄가 그 역할을 대신 |
| 표시: 칸 모양대로 테두리, 연쇄 연결은 경계의 흰 고리, 이름표에 "연쇄×1.25" | 덩어리가 커져도 족보 경계가 보이게 |
| 적 체력 웨이브마다 ×1.39 | 모양 자유 + 연쇄로 봇이 너무 강해져서 (10판 전승, 목숨 13.7 → 5판 통과) |

## 11. v1.3: 콘텐츠 1차 (보상, 새 적, 보스)
요청: 콘텐츠 좀 쌓아보자. 메모의 범위 가이드(핵심 루프 → 시너지 손맛 → 이펙트 → 볼륨) 중 볼륨.

| 추가 | 내용 | 이유 |
|---|---|---|
| 웨이브 보상 | 웨이브를 막을 때마다 3개 중 1개 (조커 2 + 즉시 1). 건너뛰기 가능 | 판마다 다른 빌드. 반복 플레이의 핵심 (발라트로 조커 구조) |
| 조커 18종, 최대 5칸 | 무늬 강화 4, 족보 강화 4(연결고리·쌍둥이·일직선·넓은 물결), 숫자 강화 3(그림 카드·작은 수·행운의 7), 카드 공급 3(큰 손·보급·재활용), 전투 4(조준경·서리·연쇄 폭발·관통탄) | 카드·족보·연쇄 고민을 더 깊게 만드는 쪽으로. 효과는 한 줄로 설명되게 |
| 즉시 보상 3종 | 와일드 카드, 보충(2장), 수리(목숨 +3) | 조커 칸이 차도 보상이 의미 있게 |
| 와일드 카드 | 아무 숫자·무늬로 쳐서 족보를 이어 줌. 흰 별 타워, 숫자 10 위력 | 막힌 덩어리를 푸는 카드. 덱빌딩의 첫걸음 |
| 새 적 3종 | 방패병(한 방 피해 감소, 최소 25%), 분열체(죽으면 둘), 재생자(초당 3% 회복) | 무늬 선택에 이유를 줌: 방패엔 ♠ 한 방, 분열엔 ♥ 범위, 재생엔 집중 화력 |
| 보스 3종 | 5 방패 거인, 10 분열 군주(탱크 넷으로), 15 재생 왕 | 보스마다 다른 대응 |
| 적 체력 웨이브마다 ×1.45 (전 ×1.39) | 보상까지 받는 것을 기준으로 | 봇: 조커를 고르면 8/10, 보상 안 받으면 0/10 |

웹 프로토타입 작업은 여기서 멈춘다 (D-062). 이 콘텐츠는 언리얼(PDCore, PDBoardWidget)로 옮겼다 (D-063, 빌드 확인 전).
